# Dify 多模态 RAG 与智能文档转写增强版

[English](README.md) | [中文](README_zh.md)

基于 **Dify 1.17.0** 的企业级多模态 RAG 增强扩展。针对 **Dify 官方上游完全不提供 PPTX 格式解析支持** 的空白，本项目从零自研了 PPTX 解析引擎，并逐步演进出视觉语言模型（VLM）装饰图智能清洗、全文档多模态转写及 Markdown 结构感知切分等全套生产级特性。

---

## 项目背景与核心痛点

在企业知识库构建中，演示文稿（`.pptx`）是技术方案、架构演进与业务总结的最主要载体。然而在接入主流 RAG 系统时存在诸多痛点：
1. **Dify 上游原生压根不支持 PPTX**：Dify 官方原版的文档白名单与抽取逻辑中完全没有 `.pptx` 分支，无法直接上传并解析 PowerPoint 演示文稿；
2. **视觉与版式信息丢失**：传统文档抽取器将幻灯片拍平成无序的纯文本流，严重破坏多栏排版、复杂图表与备注信息，导致跨页语义断裂；
3. **装饰性视觉噪声污染**：企业幻灯片普遍包含大量企业 Logo、页眉页脚条带、重复水印与修饰性图标。若未经甄别直接落库，不仅占用大量存储，还会污染多模态向量索引与前端检索渲染；
4. **分段检索与引用溯源割裂**：标准分词切分器按固定长度生硬截断，切散了上下文，且丢失了段落与源文件页码、章节层级的关联。

本扩展基于 Dify `1.17.0` 官方版本，设计并实现了端到端的多模态文档解析摄入管线：
- **从零自研补齐 PPTX 解析**：自研专用幻灯片解析器（`pptx_extractor.py`），在上游白名单与调度中心中打通 `.pptx` 链路；
- **视觉模型智能清洗**：借助多模态大模型对文档图片进行上下文二分类判定，彻底剥离企业 Logo 与水印等装饰性噪声；
- **多模态全文档转写**：将混乱排版的幻灯片与页面统一重构为结构化 Markdown，保留表格、公式，并逐字保留图片预览链接（`![image](/files/<id>/file-preview)`）与页码标记（`<!-- page: N -->`）；
- **Markdown 结构感知分块**：切分过程中动态维护 ATX 标题栈，为每个分段自动注入面包屑导航（`【章节路径】`），并智能合并碎片块；
- **向量库生命周期加固**：修复上游 Weaviate 向量库在文档删除时 ID 映射不一致导致的旧向量残留缺陷。

## 技术演进与架构设计

整个系统的落地并非盲目堆砌功能，而是顺应真实业务痛点逐步推演的工程闭环：

### 阶段一：从零自主研发 Dify 的 PPTX 支持（起步 200 行）
**Dify 官方 1.17.0 源码中压根没有 PPTX 相关代码**，不仅扩展名白名单（`api/constants/__init__.py`）将 `.pptx` 拒之门外，提取分发入口（`extract_processor.py`）也没有处理分支。
- 我们基于 `python-pptx` 从零编写了原生提取引擎（`api/core/rag/extractor/pptx_extractor.py`，最初版本仅约 200 行代码）；
- 与简单的纯文本转储不同，该模块系统性遍历幻灯片中的文本框、表格单元格几何关系、演说者备注，记录内嵌图片的映射关系，并按页产出带有标准 `page` 元数据的 Dify `Document` 对象，与 `PdfExtractor` 的页码规范对齐；
- 在 Dify 摄取入口完成分支注册，正式实现了 Dify 对 PowerPoint 格式的从无到有。

### 阶段二：发现大量重复视觉噪声，催生 VLM 视觉判定
PPTX 文件能够正常进入 Dify 之后，真实企业课件与方案材料立刻暴露出了严重问题：每一页幻灯片都充斥着企业 Logo、固定页眉、装饰性线条和全屏水印。
- 若采用朴素的跨页频率统计，遇到仅在首页/末页出现的 Logo，或每页文字微调的动态水印时极易失效；
- 为此，我们将提取流程升级为**两遍式解析架构**，并引入视觉模型判定（`decorative_image_judge.py`）：
  1. **第一遍扫描**：提取正文与表格，在图片出现处仅埋入内部占位符，记录图片的二进制哈希与出现页面，暂不落盘；
  2. **第二遍判定**：将候选图片连同其出现位置、所在页面的正文片段按批次提交给视觉语言模型（VLM）。模型基于视觉呈现与上下文关联，判定其为“装饰性（decorative）”还是“承载信息（meaningful）”；
  3. **裁决执行**：装饰图直接丢弃，不落存储也不进文本；信息图落盘并回填为标准预览链接 `![image](/files/<id>/file-preview)`。

### 阶段三：以此为灵感，推演至全文档多模态转写
VLM 在图片语义甄别上的出色表现，启发了进一步的架构飞跃：**既然视觉模型能够精准理解幻灯片的局部图文关系，为何不将整篇文档交由多模态模型进行统一重构？**
- 企业文档往往排版复杂，多栏布局、卡片式拼贴、嵌套流程图往往使规则提取出的文本支离破碎；
- 我们在 `extract_processor.py` 的关键收口处引入了多模态转写服务（`api/core/rag/extractor/transcribe_service.py`）：以整篇文档为输入单位，调度多模态模型将其转写为语义连贯、排版统一的规范 Markdown；
- **三条系统级硬约束**：
  1. **图片链接逐字保留**：转写输出必须完整保留原有的 `![image](/files/<id>/file-preview)` 占位，如若丢失则判定转写无效并触发熔断保护；
  2. **非侵入式引用溯源**：在转写文本中注入 `<!-- page: N -->` 与 `<!-- row: N -->` 注释标记，保证下游 RAG 检索命中时仍可准确定位原始页码与表格位置；
  3. **行级滑动窗口分片**：针对超长文档按行级累积切块（`TRANSCRIBE_MAX_CHARS_PER_CHUNK`），绝不截断单行，保证转写上下文连贯。

### 阶段四：工程健壮性加固与切分优化
- **全链路 Fail-Open 容灾**：多模态转写和视觉判定均采用严格的沙箱兜底。无论模型超时、配额耗尽还是网络抖动，均无缝回退至原生解析，绝不阻塞知识库索引管线。
- **结构感知分块器（`fixed_text_splitter.py`）**：针对 Markdown 增强切分逻辑，维护 ATX 标题栈，在每个切片头部注入带有面包屑的 `【章节路径】`，并引入碎片合并机制，防止标题或段落成为孤立碎块。
- **Weaviate 向量残留修复（`weaviate_vector.py`）**：修复了上游向量库写入时使用 UUID5 哈希而删除时使用 Dify 文档 ID 导致删除失效的问题，支持按 `doc_id` 批量清理并优雅降级。

## 核心特性一览

- **补齐 Dify 缺失的 PPTX 支持**：填补上游官方空白，支持 PPTX 完整解析、表格还原、演说者备注提取与图片关联。
- **高保真多模态转写**：支持 PPTX、PDF 等多类文档直接转写为规范 Markdown，自动还原表格、列表及公式。
- **智能去噪与 Logo 过滤**：借助 VLM 上下文理解能力，自动剔除无信息量的背景图、徽标与装饰线条。
- **端到端可追溯性**：自动生成页码标记与章节路径，彻底解决大模型生成答案时的溯源断链问题。
- **架构零侵入与高兼容**：转写服务挂载于抽取器与索引处理器之间，完全兼容 Dify 现有的分段模式（段落检索、父子切分、QA 分割）。
- **生产级容错防御**：转写与判定失败自动无缝降级，保障高可用吞吐。

## 配置指南

在 `docker/.env` 中增加以下配置项（修改后需重建并重启服务生效）：

```bash
# 转写总开关
TRANSCRIBE_ENABLED=true

# 视觉模型配置（需与 Dify 控制台中已添加的 Provider 和模型一致）
TRANSCRIBE_MODEL_PROVIDER=langgenius/openai_api_compatible/openai_api_compatible
TRANSCRIBE_MODEL_NAME=qwen3.8-27b
TRANSCRIBE_IMAGE_DETAIL=low

# 装饰图视觉判定开关（true 为走大模型判定，false 降级为跨页频率启发式）
TRANSCRIBE_DECORATIVE_JUDGE=true

# 输出语言与提示词（留空使用内置 DEFAULT_TRANSCRIBE_PROMPT）
TRANSCRIBE_LANGUAGE=中文
TRANSCRIBE_PROMPT=
TRANSCRIBE_TEMPERATURE=

# 超长文档分片预算与页码偏移
TRANSCRIBE_MAX_CHARS_PER_CHUNK=12000
TRANSCRIBE_MAX_CHUNKS=0
TRANSCRIBE_PAGE_OFFSET=1
```

### 关键参数解析

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `TRANSCRIBE_ENABLED` | `false` | 转写服务总开关。关闭时完全跳过转写，直接使用自研基础解析产物。 |
| `TRANSCRIBE_MODEL_PROVIDER` | `""` | 模型提供方 ID，需与控制台配置保持一致。 |
| `TRANSCRIBE_MODEL_NAME` | `""` | 具备视觉理解能力的多模态模型名称。 |
| `TRANSCRIBE_DECORATIVE_JUDGE` | `true` | 是否启用视觉模型对装饰图进行逐张判定；关闭后仅按跨页重复频率过滤。 |
| `TRANSCRIBE_IMAGE_DETAIL` | `low` | 送入视觉模型的图片细节档位（`low` 或 `high`）。 |
| `TRANSCRIBE_LANGUAGE` | `""` | 目标转写语言（如 `中文`、`English`），留空则跟随文档原本语言。 |
| `TRANSCRIBE_MAX_CHARS_PER_CHUNK` | `12000` | 超长文档切片字符上限，转写按分片分批提交，防止模型上下文溢出。 |
| `TRANSCRIBE_PAGE_OFFSET` | `1` | 页码起始编号，用于生成 `<!-- page: n -->` 定位标记。 |

## 快速上手与验证

### 1. 生效配置
修改 `docker/.env` 配置后，重新构建并启动 `api` 与 `worker` 容器：

```bash
docker compose build api worker
docker compose up -d api worker
```

### 2. 检查配置加载
进入容器验证配置是否已正确识别：

```bash
docker compose exec api python -c "from configs import dify_config; print('Transcribe Enabled:', dify_config.TRANSCRIBE_ENABLED)"
```

### 3. 运行单元测试
执行结构感知切分器等新增特性的单元测试套件：

```bash
docker compose exec api uv run pytest tests/unit_tests/core/rag/splitter/test_text_splitter.py -q
```

### 4. 实际效果验证
1. 在 Dify 知识库中上传一份包含企业 Logo、多栏排版与图表的 `.pptx` 文件；
2. 观察控制台日志：
   ```bash
   docker compose logs -f api | grep -E "transcribe|decorative"
   ```
3. 索引构建完成后，进入文档分段详情：
   - 正文被转换为规范排版的 Markdown，表格保持格式完好；
   - 每个分段头部自动带有 `【一级章节 > 二级小节】` 导航；
   - 包含业务信息的插图完好保留了预览链接，而每页重复的 Logo 及水印已被彻底清理。
